Experimental ARM64 Steam **Metal** development preview for iPhone. Download the real **SomethingPC-SteamARM64.ipa** from Assets and sign it with your sideloading tool.

This performance update avoids recopying the installed diagnostic/controller payload and startup scripts on every boot. It reuses them only after checking exact bytes, file types, root ownership, modes and symlink targets; changed or damaged files still require an update. The disk exposes one virtio-blk queue per guest CPU through the existing IOThread, with guest flushes preserved. The foreground VM thread explicitly uses user-initiated scheduling. These changes reduce avoidable work; their effect on Steam installation and interaction must be measured on the phone.

The warmed integer test does not measure Steam decompression, startup or game installation.

**Backbone Pro / gamepads:** iOS extended gamepads are forwarded over a private local virtio-serial channel to up to four real Linux uinput gamepads with an Xbox-style layout. Sticks, analog triggers, D-pad, A/B/X/Y, shoulders, Menu/View, stick clicks and the standard Guide input are forwarded. Steam and games can see ordinary Linux gamepad devices; there is no network input listener. Open session controls to see the controller name and Linux acknowledgement, then tap **Open Steam Big Picture** for controller navigation. Native app panels release guest inputs and retain menu navigation. Backgrounding and unplugging release input; a two-second guest watchdog removes a controller if host updates stop. Rumble and Backbone-specific shortcut functions are not implemented. Physical Backbone Pro behavior still needs device testing.

The controller build gate boots the packaged QEMU, sends actual states through virtio-serial, and requires Linux udev gamepad classification, Steam-user read permission, all eleven digital buttons, both sticks, both analog triggers, D-pad, release and hotplug/reconnection. Protocol tests also cover fragmented/corrupt packets, stale/wrapped sequences and watchdog cleanup. This does not prove game-specific Steam Input mappings or playable performance.

CPU comparison runs a checksum-verified dependent-integer workload outside the VM in native iOS Swift, then inside Linux in ARM64 C and x86-64 C through FEX, with one worker and all guest cores. It records guest per-core busy/iowait percentages, Steam helper CPU use, available memory, swap, app CPU/RAM, Low Power Mode and thermal state. Compiler and language differences affect the native iOS comparison. The ARM Linux CPU is still emulated by QEMU TCG; matching ARM architectures does not give this guest native execution speed.

GPU comparison draws and reads back real red/green/blue shader pixels, then renders 60 frames at 800×500 with 16 draws per frame. It compares ARM64 Mesa with an x86-64 binary through **unmodified FEX 2609.1** and its EGL/GL forwarding libraries, using a separate bundled test root. It measures submission, synchronized completion and swap times. Progress output is outside measured sample/frame intervals. Render FPS describes this diagnostic workload, not game FPS or GPU utilization. This GLES test does not validate Vulkan, DirectX, Wine or Proton games, and does not change Steam's FEX installation or configuration.

The preview 13 readback, pointer and disk/cache changes remain: GPU updates are combined per display tick; motion retains only the latest pending position; disk work uses a separate IOThread with flushes preserved; the JIT cache is 256 MiB. **This release adds diagnostics; it does not claim that the device slowdown is fixed.**

This backend uses virgl → ANGLE → Metal. The owner reported a working virgl renderer/readback check on iPhone with preview 11, but very poor responsiveness and a Linux Steam process crash. The new release gates require an actual guest GL renderer/pixel-readback check, moving primary-color GL pixels through the iPhone display callback, Steam CEF virgl compositing/WebGL, measured CEF click/animation-frame response and QMP input acknowledgment, persistent storage and clean shutdown on a hosted Mac. CI uses the same minimal framework closure as the IPA, including dynamically loaded ANGLE EGL/GLESv2 providers and their resources. Missing-provider controls must return an error without SIGABRT. The IPA archive must contain both providers with valid iPhone binaries and required exports. Mac measurements do not predict iPhone performance.

The overlay distinguishes **Software selected**, **Metal requested · unverified**, **virgl → Metal verified**, and a software fallback/readback failure. The verification refers to the guest GL driver and a rendered pixel; it does not prove that every application, Steam CEF or a game's Vulkan renderer uses that driver. GPU utilization is unavailable. **Performance** shows the last VM input acknowledgment time; this is distinct from Steam drawing its response. **Share graphics report** exports build/backend/hardware diagnostics, acknowledgment time and thermal state without account details or full logs.

A checksum-verified boot update changes three reserved My-pc startup scripts, with backups, and installs the separate diagnostic runtime under `/usr/local/lib/my-pc/hardware-tests` and the gamepad bridge under `/usr/local/lib/my-pc/controller` with its named systemd unit.
