# Build4000026: changing Linux output with three buffers

This is the next material device gate after the accepted build25 worker/RCU
retirement run. It keeps the selected ARM Linux/QEMU TCG/Venus/native Metal
architecture and adds a new producer/release path. It does not reuse the old VM
app, native preview or Madeira application as its implementation base.

The actual ARM Linux payload compiled in run37249739205 at
`c17f369ff17df6337a77dc90e6780232a2f859ec`. It retains the exact accepted kernel
and previous immutable diagnostic binaries and adds `vk-moving-gate`. Linux
boot controls rejected missing/2D-only graphics; the software Vulkan ICD was
rejected before moving rendering. The actual bidirectional UART prerequisite
passed run37249739190 at the same source: valid and byte-fragmented replies
passed; wrong session/resource, corrupt CRC, partial and missing replies failed.
These hosted Linux checks establish no iPhone GPU result.

The fresh producer exports exactly three 1280x720 linear BGRA8 allocations and
generates 120 changing shader phases. Its explicit local UART protocol carries
session/resource/incarnation/content identities and matching binary releases.
The native adapter checks the actual Metal texture/buffer alias, device, layout
and bounds, then samples that source into the actual screen drawable. Every
source release follows actual Metal GPU terminal completion, posted onto one
transport executor. Linux completes a separate external-queue ownership
reacquisition and fence wait before reuse. The final three acquisitions drain
the pool before shutdown. A CPU timeout cannot authorize reuse.

Two guest and two native full-image readbacks verify first/last content only;
ordinary frames have no full-image CPU readback and no artificial dwell. Exactly
120 offers/releases and 120 reacquisitions (including the final drain) must join
to three resource identities, 120 install generations and actual GPU draws.
Native command status, source recycling and actual positive drawable timestamps
have separate receipts. Zero/missing display time is kept incomplete. Neither
the duration of this bounded gate nor the Metal HUD is a game FPS measurement.

The local socketpair is a diagnostic guest release mechanism. It does not add
production KMS/Wayland/WSI fencing to the existing exported-buffer kernel path.
Real compositor integration remains required before a SteamOS desktop can be
accepted. The host never mutates QEMU state from a Metal callback. Pinned QEMU
source adopts the numerical socket FD and closes it during chardev cleanup;
the host joins the reader after the retired engine worker and does not close
the transferred FD again. Timeout keeps outstanding objects alive and marks
acceptance incomplete.

The build25 same-thread RCU unregister and joined worker remain mandatory.
The Metal observation limit is bounded at1024 rather than256 for the longer
workload. Recovery receipts are bounded at2MiB and serial logs at1MiB so joined
moving evidence can be exported intact. Native recovery tests verify complete
structured receipts and explicit truncation beyond those bounds. The code has
separate synthetic receipt rejection/ownership tests; they are not phone proof.
