Experimental ARM64 Steam **Metal** development preview for iPhone. Download the real **SomethingPC-SteamARM64.ipa** from Assets and sign it with your sideloading tool.

Update the existing My-pc app, restart it, and open **Library → Apps → Steam ARM64**. Before startup select **Graphics → Metal (experimental)**, enable JIT and open Steam. A saved Software choice is preserved and shows a **Use Metal graphics** button. Software remains the recovery option. CPU cores default to all available, normally six on iPhone 15 Pro Max; the Linux desktop is 1280×800. The pointer, touch/trackpad controls and CPU/RAM/display-FPS monitor are included.

The owner reports that Steam is still slow, and both preview 19 diagnostics stopped reporting at `sampling-idle` before a guest benchmark result appeared. The native iOS CPU test completed in about 4.35 ms on that phone. This update puts Linux activity sampling in a separate helper with a three-second timeout so a blocked sampler cannot prevent CPU/GPU workloads from running. The report marks missing activity measurements as unavailable. CI now exercises this same idle-sampling and test-runner path instead of only invoking the workload binaries directly.

Tap the desktop's new **Tests** button to open a full-screen test page. Settings also use a full-screen page with a fixed test button instead of a scrolling pop-up menu or draggable sheet. Pause downloads and close games; leave Steam open to measure its idle CPU load. Run **Run CPU**, then **Run GPU (FEX)**, and tap **Share test report**. The progress bar, percentage, elapsed time, last Linux heartbeat, test buttons and Stop test control stay fixed while results scroll separately. Progress reflects completed samples/frames; elapsed time does not manufacture work completion. CPU phases have a 30-second timeout and GPU phases a 60-second timeout. If the guest stops sending heartbeats for 45 active seconds, or the test lasts 180 active seconds, the app requests test-only cancellation and identifies a missing response. Background time is excluded from these host deadlines. Temporary inactive UI states no longer pause Linux; actually backgrounding My-pc still does.

No account files, command lines or Steam logs are included in the shared report. The test window closes automatically and results remain in My-pc. Stop targets only the diagnostic runner below its own test window; Steam's files and settings are preserved.

CPU comparison runs a checksum-verified dependent-integer workload outside the VM in native iOS Swift, then inside Linux in ARM64 C and x86-64 C through FEX, with one worker and all guest cores. It records guest per-core busy/iowait percentages, Steam helper CPU use, available memory, swap, app CPU/RAM, Low Power Mode and thermal state. Compiler and language differences affect the native iOS comparison. The ARM Linux CPU is still emulated by QEMU TCG; matching ARM architectures does not give this guest native execution speed.

GPU comparison draws and reads back real red/green/blue shader pixels, then renders 60 frames at 800×500 with 16 draws per frame. It compares ARM64 Mesa with an x86-64 binary through **unmodified FEX 2609.1** and its EGL/GL forwarding libraries, using a separate bundled test root. It measures submission, synchronized completion and swap times. Progress output is outside measured sample/frame intervals. Render FPS describes this diagnostic workload, not game FPS or GPU utilization. This GLES test does not validate Vulkan, DirectX, Wine or Proton games, and does not change Steam's FEX installation or configuration.

The preview 13 readback, pointer and disk/cache changes remain: GPU updates are combined per display tick; motion retains only the latest pending position; disk work uses a separate IOThread with flushes preserved; the JIT cache is 256 MiB. **This release adds diagnostics; it does not claim that the device slowdown is fixed.**

This backend uses virgl → ANGLE → Metal. The owner reported a working virgl renderer/readback check on iPhone with preview 11, but very poor responsiveness and a Linux Steam process crash. The new release gates require an actual guest GL renderer/pixel-readback check, moving primary-color GL pixels through the iPhone display callback, Steam CEF virgl compositing/WebGL, measured CEF click/animation-frame response and QMP input acknowledgment, persistent storage and clean shutdown on a hosted Mac. CI uses the same minimal framework closure as the IPA, including dynamically loaded ANGLE EGL/GLESv2 providers and their resources. Missing-provider controls must return an error without SIGABRT. The IPA archive must contain both providers with valid iPhone binaries and required exports. Mac measurements do not predict iPhone performance.

The overlay distinguishes **Software selected**, **Metal requested · unverified**, **virgl → Metal verified**, and a software fallback/readback failure. The verification refers to the guest GL driver and a rendered pixel; it does not prove that every application, Steam CEF or a game's Vulkan renderer uses that driver. GPU utilization is unavailable. **Performance** shows the last VM input acknowledgment time; this is distinct from Steam drawing its response. **Share graphics report** exports build/backend/hardware diagnostics, acknowledgment time and thermal state without account details or full logs.

A checksum-verified boot update changes three reserved My-pc startup scripts, with backups, and installs the separate diagnostic runtime under `/usr/local/lib/my-pc/hardware-tests`. It preserves the existing Linux disk, downloaded Steam client, account and games. The installed kernel must match the update; a mismatch refuses Metal and leaves Software usable. If Metal startup fails, restart My-pc and choose Software. Do not reset the Linux installation.

Steam still downloads directly from Valve. Existing Steam data should remain when updating the same signed app; deleting the app deletes its sandbox. New setup needs approximately 13 GB free. This is a JIT sideloading preview, not the separate JIT-free product or an App Store build. Audio, Windows-game translation/Vulkan and gaming performance remain unfinished. Corresponding runtime sources and IPA checksum are attached.
