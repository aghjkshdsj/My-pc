# Immutable image resource readback gate 4000020

This host correction retains the exact successful 4000019 ARM Linux payload and native engine. Build checks do not inherit a phone import pass.

## Problem and resulting behaviour

Native scanout installation/flush/disable generations describe display lifetimes. A Linux modeset/dirty update can reinstall the same immutable export resource with a newer generation. Counting readbacks by generation can consume both allowed readbacks on the first image, preventing the second distinct image from being checked.

The production budget now consumes each distinct immutable guest resource once. A repeat with identical format, dimensions, stride, offset, crop and orientation is tracked without another GPU readback. Changed metadata is rejected. Borrowed texture pointers are never retained by the budget; the actual consumer still retains its texture/backing until GPU completion. Capacity remains two resources and event capture remains bounded at 64.

Both native and independent receipt validators retain strictly ordered, monotonically increasing installation generations and require each installation's valid flush/disable lifecycle. Repeated resource installations are allowed, but two distinct producer resources and native consumers must match phases 0 and 41, their first flush generations, exact layouts/devices/formats, zero mismatches, producer/consumer completion and final cleanup. Two copies of phase 0 cannot pass. Unknown resources, missing flushes, stale generations, active overlap, altered layout and uncompleted release remain failures.
