# Build 4000016: complete recovery receipts within explicit bounds

This host update keeps the exact Linux kernel/Mesa payload, QEMU/GL/Venus
engine and MoltenVK completion-observer binaries from build 4000015. It changes
recovery sharing and the desktop evidence verifier, without replacing the Linux
execution or graphics architecture. Earlier packages and local reports remain
preserved. Public compile/package records never inherit an earlier phone result.

The recovery exporter previously kept only the last 128 KiB of every file.
Ordinary structured receipts could exceed that limit after engine metadata and
the bounded native completion ledger were included. The exported suffix was
explicitly marked truncated but no longer parseable JSON. Known JSON diagnostic
files now have a 512 KiB limit; plain logs retain their 128 KiB limit. Each entry
records file bytes, captured bytes, capture limit and truncation. Oversized JSON
remains explicitly incomplete and cannot pass the evidence verifier. Selection
still includes at most three recent journal directories, three known report
files and two disposable Linux log directories. Nothing is deleted or uploaded
automatically. Unrelated user files and final-component symlinks remain excluded.

Native Swift recovery fixtures exercise the real production journal, including
a parseable complete receipt larger than the prior limit, a JSON file larger
than the new limit, bounded plain-text tails, abrupt-exit/reopen behavior,
completed and timed-out tests, retained/cancelled sharing, stale/corrupt markers
and file/path exclusions. These are native fixture tests, not a phone crash or
OS stack trace. A recovery export alone never establishes the cause of closure.

The unchanged production native ledger permits successful completed buffers
with equal positive GPU start/end timestamps at the reported precision. They
do not count toward its minimum of two buffers with strictly positive duration.
The desktop verifier previously rejected all equal positive timestamps, despite
matching native status, errors, identity and sufficient other timed work. It now
matches that bounded timing rule. Python and production C++ fixtures retain
zero-duration observations alongside sufficient timed work, and reject using
them to replace required timed work. Stale nonces, wrong device/scope, errors,
missing/duplicate callbacks, overflow and invalid timestamps remain rejected.

Apple documents the native [GPU start](https://developer.apple.com/documentation/metal/mtlcommandbuffer/gpustarttime)
and [GPU end](https://developer.apple.com/documentation/metal/mtlcommandbuffer/gpuendtime)
observations. Duration is derived only when end is strictly greater than start;
the observations are not game frames or FPS. The observer's registration and
actual submission site are described in [build 4000015](GPU-GATE-4000015.md).

Expected release checks are 63 Python evidence tests, 28 native guest receipt
checks, 27 production native ledger checks, native recovery/capture fixtures,
physical ARM64 iOS Release compilation and exact public IPA/source verification.
The release remains pending until actual CI and package checks finish.

Per-device acceptance lives in `evidence/device/`, outside uploads. Complete
game graphics, shared-image ownership/import, moving guest frames, screen
presentation, SteamOS/Steam/FEX/Proton and sustained performance remain separate
acceptance gates. The [DroidDeck blueprint](DROIDDECK-BLUEPRINT.md) remains the
functional component plan.
