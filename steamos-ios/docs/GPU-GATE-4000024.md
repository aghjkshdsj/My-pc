# Build4000024: worker retirement and local OS crash diagnostics

This host change follows the bounded eight-frame package. Guest image production,
native graphics dependencies, receipt pixel/identity checks and original strict
display timing requirements remain pinned. It does not accept continuous
animation, mutable buffer reuse, a Linux compositor or game performance.

The previous completion flag was published before the engine worker's
autorelease pool drained. The host now publishes completion after that drain
and joins the worker before parsing receipts. A timeout detaches the still-live
worker and preserves the interrupted-run marker; timeout cannot become a passed
result because of a subsequent racing completion. New durable checkpoints
bracket serial reading, kernel/ABI parsing, guest Vulkan parsing, native Metal
observer finalization, frame import and frame screen finalization. This closes
a concurrent-finalization window and improves localization. It does not
establish the cause of any earlier owner-reported process termination.

The app subscribes to Apple's MetricKit diagnostics, retaining the subscriber
for its lifetime. When the OS supplies a crash payload, a utility queue saves
the original JSON metadata locally. It neither uses a fatal-signal handler nor
interferes with QEMU/JIT fault handling. Payloads larger than 384KiB, malformed
JSON and empty crash lists are refused; saved envelopes are limited to 512KiB.
Share logs includes at most three recent complete system crash envelopes, with
existing symlink exclusion. Existing reports and user data are preserved.
Collector source/build identity is separate from the payload's original crash
metadata: no active Linux nonce association is invented. No automatic upload.

[Apple's MetricKit documentation](https://developer.apple.com/documentation/metrickit)
describes OS delivery; actual delivery on a sideloaded, debugger-enabled phone
still requires observation. The iOS26-compatible MX subscriber API is used with
the build SDK; the newer iOS27 async API is a future migration. Missing delivery
does not establish no crash, and this cannot reconstruct earlier faults.
[Apple crash reports](https://developer.apple.com/documentation/xcode/acquiring-crash-reports-and-diagnostic-logs)
remain the fallback for exception type, termination reason and fault stack.

Release compilation explicitly produces a host dSYM. A separate verifier requires
one bounded, nonzero ARM64 Mach-O UUID in the actual packaged executable and
its dSYM, and rejects mismatches. The dSYM and package/source/build/UUID receipt
are published alongside the IPA. This supplies exact host symbolication data;
upstream native frameworks still need their own matching symbols if they fault.
Synthetic rejection tests establish parser/storage behavior, not a phone crash
cause or reliable OS delivery. Physical iOS Release and independent package/
symbol checks are required before publication. Phone hardening verification is
separate from package verification.

The next graphics implementation is reused-buffer ownership and real
compositor/WSI integration. ABI1 exposes installation/flush generations and a
borrowed texture, but does not expose a guest frame identity or a host consumer
release fence. Immutable resource-ID deduplication in the eight-frame diagnostic
cannot be reused for changing contents. An explicit release path must connect
native completion to guest buffer reacquisition before testing a bounded pool
and then the actual desktop/compositor. More immutable frames alone do not
complete that work. See PRESENTATION-GATE.md and ARCHITECTURE.md.

CPU execution remains QEMU TCG software system emulation. Native Metal is a
separate graphics path; hardware virtualization is not verified. Full SteamOS
desktop/Game Mode/ARM Steam/CEF, FEX/Proton, audio/controllers/network/downloads,
overlays/plugins and startup/game/thermal targets remain unfinished. No
architecture substitution or prior application implementation is adopted.
