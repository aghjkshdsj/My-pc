# Build4000027: distinguish display refresh from changing content

The host adapter previously treated each native installation generation as a
new content frame. A display backend can reinstall the same resource and flush
the already claimed content ticket again. This caused flush-not-armed to
quarantine the release transport, preventing the next producer offer.

The fresh host now identifies content by session/resource/incarnation/serial.
An already claimed ticket can refresh across installation generations without
submitting another native reader or issuing a release. The original actual
GPU completion still owns that release, and Linux must finish its independent
Vulkan ownership reacquisition before reuse. A different new ticket still
requires an armed producer fence and a fresh installation generation. Invalid
layout, stale session/incarnation, early reuse and wrong resource remain errors.

All installation/flush/disable events remain in the bounded receipt. Each
flush is explicitly joined either to its one actual content draw or to the
last claimed ticket for that resource. Refresh records have zero new readers
and zero releases; they cannot substitute for any of the 120 required actual
draws, releases or reacquisitions. Complete event coverage and the final drained
pool remain mandatory. Source recycling and actual positive display timestamps
retain separate verdicts. A zero timestamp remains incomplete.

Native source tests replay same-resource reinstallation while a GPU reader is
pending and after release, then exercise a new resource and a reacquired ticket.
They reject stale identity, unregistered/producing state and premature reuse.
Receipt controls replay 120 content frames with 120 additional reinstalls,
preserve 120 real-source fixture readers/releases/acquisitions, and reject hidden
work, wrong tickets, missing events and incomplete ownership. These are
synthetic rejection/source tests; they do not execute an iPhone GPU.

The same selected QEMU TCG/Venus/virgl/MoltenVK engine and complete ARM Linux
payload remain pinned. The fix changes the fresh host, not the engine or guest
binary. It retains same-thread RCU retirement, joined workers, crash-log sharing,
StikDebug enablement, the original immutable diagnostics and full archive/Android
blueprint coverage. Corresponding-source/license bundles are retained.
