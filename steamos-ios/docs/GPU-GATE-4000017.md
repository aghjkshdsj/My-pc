## Export-format source correction in build 4000018

Pinned Mesa 26.2.2 `src/virtio/vulkan/vn_physical_device.c` explicitly rejects
external DMA-BUF image queries using legacy tiling. An advertised external-memory
extension is insufficient. Build 4000017 requests `VK_IMAGE_TILING_LINEAR`;
[build 4000018](GPU-GATE-4000018.md) queries and creates the image using
`VK_IMAGE_TILING_DRM_FORMAT_MODIFIER_EXT` with explicit `DRM_FORMAT_MOD_LINEAR`.
It verifies the returned modifier and queries memory plane 0, retaining all pixel,
layout, fence and ownership checks. This is a correction within the current
Linux/Venus/Metal architecture, not a replacement architecture or success override.

Khronos specifies the modifier query in
[VkPhysicalDeviceImageDrmFormatModifierInfoEXT](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceImageDrmFormatModifierInfoEXT.html)
and the matching creation list in
[VkImageDrmFormatModifierListCreateInfoEXT](https://docs.vulkan.org/refpages/latest/refpages/source/VkImageDrmFormatModifierListCreateInfoEXT.html).
The exact Mesa archive has SHA-256
`eeb29ca7e56cfaa8e8a79538dcf834e3b18e501c31bef5145e959ea437cc4216`.
No unsupported query is relabeled successful.

QEMU TCG remains software system emulation. Native host code and Metal GPU
